# Implementation Plan: Login de Usuario con Contraseña

**Branch**: `feature/002-login-usuario` | **Date**: 2026-10-05 | **Spec**: [spec.md](./spec.md)

## Summary

Reemplazar el login de solo correo del spec 001 por un login con identificador (correo o nombre
de usuario) y contraseña, verificado contra una tabla `users` de PostgreSQL. La contraseña se
guarda como hash bcrypt con sal. Se agregan límite de intentos fallidos, un script de seed para
crear el usuario inicial y una pantalla de login funcional sin diseño visual definido.

## Technical Context

**Language/Version**: TypeScript estricto en todo el monorepo (sin cambios respecto al spec 001).

**Primary Dependencies**: `bcryptjs` para hashing (implementación JS pura, sin binarios nativos,
compatible con el contenedor Docker y con el runtime de Node de Auth.js). Drizzle ORM y
`postgres` ya existen en `packages/db`.

**Storage**: PostgreSQL. Nueva tabla `users` en `packages/db/schema/users.ts` y migración
`0001_create_users.sql` generada con Drizzle Kit.

**Testing**: Vitest para la lógica pura en `packages/core` (hash, normalización, política de
bloqueo). Para `packages/db` (repositorio, migración y seed) se usa `@electric-sql/pglite`, que
ejecuta Postgres real en proceso, sin servicio externo. Playwright para el flujo de login completo.

**Target Platform**: Next.js (Node runtime) en Vercel y en local.

**Project Type**: Monorepo web; se agrega un script de CLI en `packages/db`.

**Performance Goals**: Login < 3 s (SC-001). `bcrypt` con costo 12 cumple con holgura.

**Constraints**: Sin registro público (FR-010). Contraseña nunca en texto plano ni reversible (FR-003).

**Scale/Scope**: Un usuario real; el diseño soporta más sin cambios de esquema.

## Decisiones clave

- **Hash bcrypt (bcryptjs) con costo 12**, no "encriptación": una contraseña debe ser verificable
  pero no recuperable, y un hash cumple eso mejor que cualquier cifrado reversible.
- **Bloqueo por cuenta existente**: el contador de intentos fallidos y `locked_until` viven en la
  fila del usuario. Para identificadores que no existen no hay fila donde contar, así que no se
  bloquean; esto es una limitación conocida, aceptable para una app de un solo usuario, y se
  documenta en el spec como trade-off.
- **Mensaje genérico**: `authorize` devuelve `null` tanto si el identificador no existe como si la
  contraseña falla, y se ejecuta una comparación bcrypt contra un hash señuelo cuando no hay
  usuario, para que el tiempo de respuesta no revele qué identificadores existen.
- **Redirect manual**: el login usa `redirect: false` y muestra el error en la misma pantalla, sin
  redirigir a una página de "denegado". Por eso se elimina `/denied`.
- **Middleware**: exige una sesión válida de Auth.js; ya no compara contra `AUTHORIZED_EMAIL`,
  porque la identidad ahora la garantiza la base de datos.

## Project Structure

```text
packages/core/src/auth/
├── password.ts            # hashPassword / verifyPassword (bcryptjs), dummy hash for timing
├── identifier.ts          # normalizeIdentifier (trim; lowercase if it looks like an email)
└── lockout.ts             # pure policy: isLocked, nextFailureState, MAX_ATTEMPTS, LOCK_WINDOW
packages/core/tests/auth/  # Vitest for the three modules above

packages/db/schema/users.ts            # users table (shared columns + username, email, password_hash, failed_attempts, locked_until)
packages/db/migrations/0001_*.sql      # generated by drizzle-kit generate
packages/db/src/user-repository.ts     # findByIdentifier, createUser, recordFailure, resetFailures
packages/db/src/seed-user.ts           # CLI: --email --username --password; idempotent, no overwrite
packages/db/tests/                     # PGlite-backed tests: migration, repository, seed

apps/web/lib/auth.ts                   # Credentials authorize uses core + user-repository
apps/web/middleware.ts                 # session required only
apps/web/app/(auth)/login/page.tsx     # identifier + password form, inline generic error
apps/web/app/(auth)/denied/            # removed
apps/web/tests/e2e/login.spec.ts       # updated for the new flow
```
